# 概念讲解范式与已验证示例

本文件为 `concept-explainer` skill 的参考库，定义四角度的讲解范式，并给出三套已验证示例（死锁 / 递归 / 事务隔离级别），作为生成时的保真模板。新增概念时优先对齐下列结构与语气。

## 一、四角度通用范式

| 角度 | 目标 | 写法要点 |
|------|------|----------|
| 生活类比 | 把抽象映射到具体 | 1–2 段日常场景；类比末尾点明"现象↔概念要素"的对应；可补一句"类比边界"防过度延伸 |
| 示意图描述 | 让脑补有骨架 | 优先 ASCII / 流程 / 状态图；写清元素个数、箭头方向、标注文字；复杂流程用顺序步骤或状态流转 |
| 最小可运行代码 | 跑一遍就懂 | 自包含、可复制、含入口；附"运行预期"+"哪行对应概念哪点"；不适合代码的概念改"最小计算示例 + 公式" |
| 学生常见误解 | 排雷 | 3–5 条；格式 `误解：… → 正解：…`；优先来自真实教学反馈 |

## 二、分学科偏好

- **编程 / 计算机**：代码卡片必给，默认 Python；类比用系统/生活场景（如交通、排队、借书）。
- **数学**：代码卡可换"伪代码 / 计算示例 + 关键公式"；示意图偏结构图（集合、函数映射、数轴）。
- **物理 / 通用**：强调生活类比；代码卡按需给"可交互小实验"或省略；示意图偏受力图/状态图。

## 二之补、难度 × 受众矩阵（筛选维度如何改变四角度）

### 难度轴（生成期 + 交互双层）

| 难度 | 基础层 | `.adv[data-depth="1"]`（中/难可见） | `.adv[data-depth="2"]`（仅难可见） | 误解条数 |
|------|--------|--------------------------------------|--------------------------------------|----------|
| 易(0) | 必给，最短代码，零/少术语 | 不写 | 不写 | 2 |
| 中(1) | 必给 | 进阶类比 + 进阶代码/规避 + 加 1 条误解 | 不写 | 3 |
| 难(2) | 必给 | 同上 | 时序/状态级示意图 + 再加 1 条深坑 | 4 |

> 基础内容**不带** `data-depth`（始终可见）；只有"超出当前难度才需要"的内容进 `.adv`。

### 受众轴（生成期决定语气；HTML 用 `.callout[data-aud]` 做专属提示）

| 受众 | 语气 / 术语 | 代码 | 误解聚焦点 | 专属提示放置 |
|------|------------|------|-----------|--------------|
| 中学生 | 纯生活比喻，零术语黑话 | 可省略或伪代码 | "字面直觉错"（如以为递归=循环） | `.callout[data-aud="中学生"]`：如何先建立直觉 |
| 大学生 | 类比可带专业语境 | 最小可运行代码必给 | "概念混淆"（如死锁 vs 饥饿） | 一般不额外加 |
| 自学者 | 类比亲切、鼓励性 | 最小可运行 + 避坑 | "易卡住的工程细节" | `.callout[data-aud="自学者"]`：学习路径建议 |
| 教师 | 严谨、可引用教材表述 | 可给"反例代码" | "学生常犯错误归因" | `.callout[data-aud="教师"]`：讲授话术 / 提问预设 |

> 一个概念可在一个卡片里同时挂多个受众 callout（各写各的 `data-aud`），页面按所选受众只显示对应的一条。

## 三、已验证示例

### 示例 A：死锁（Deadlock，编程）

- **生活类比**：两人吃饭各拿一只筷子（A 拿左、B 拿右）互相等对方放下——谁都不松手就永远吃不上。对应：两个线程各持一把锁，互等对方释放。
- **示意图**：四箭头环路 `线程1 →(持锁A) 等锁B→ 线程2 →(持锁B) 等锁A→ 线程1`，标注"环路等待 = 死锁四大条件之一"。
- **最小代码**（Python `threading`）：
  ```python
  import threading, time
  A, B = threading.Lock(), threading.Lock()
  def t1():
      with A:
          time.sleep(0.1)
          with B: print("t1 done")   # 持A等B
  def t2():
      with B:
          time.sleep(0.1)
          with A: print("t2 done")   # 持B等A
  threading.Thread(target=t1).start()
  threading.Thread(target=t2).start()
  ```
  运行预期：大概率两线程都卡住不输出（死锁）。关键行：`with B` / `with A` 处互相等待。
- **常见误解**：
  - 误解：死锁只在单线程 → 正解：死锁恰是多执行流互相阻塞的产物。
  - 误解：加锁就一定安全 → 正解：锁的"顺序不一致"正是死锁根源，统一加锁顺序可破。
  - 误解：死锁会报错 → 正解：死锁通常静默卡死，无异常，最难排查。

### 示例 B：递归（Recursion，编程）

- **生活类比**：俄罗斯套娃——打开一个娃发现里面还有更小的同款娃，直到最小的空娃（基线条件）才开始一层层合上。对应：函数调用自身，直到触底再逐层返回。
- **示意图**：`f(3)→f(2)→f(1)→f(0)[基线]`，回程标注"返回值沿调用栈逐层上浮"。
- **最小代码**（阶乘）：
  ```python
  def fact(n):
      if n <= 1: return 1        # 基线条件，防无限
      return n * fact(n - 1)     # 自调用 + 向基线收敛
  print(fact(4))                # 24
  ```
  运行预期：`24`。关键行：`if n <= 1` 是基线，缺了会 `RecursionError`。
- **常见误解**：
  - 误解：递归会无限循环 → 正解：缺基线/不收敛才爆栈，正确递归必触底。
  - 误解：递归比循环慢就没用 → 正解：树/分治结构天然递归，代码更直观，性能可用尾递归/记忆化补偿。
  - 误解：return 写不写都行 → 正解：非基线分支必须 `return` 自调用结果，否则返回 `None`。

### 示例 C：事务隔离级别（Transaction Isolation，数据库）

- **生活类比**：图书馆自习室——只读不写的人（读事务）和多人在改同一份笔记（写事务）共处。隔离级别就是"允许你看到别人改到一半的笔记到什么程度"。
- **示意图**：四级阶梯 `读未提交→读已提交→可重复读→串行化`，每级标注"能避免的异常：脏读/不可重复读/幻读"。
- **最小代码**（SQL 示意 + Python 伪调用）：
  ```sql
  SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
  BEGIN;
  SELECT balance FROM account WHERE id=1;  -- 看不到未提交的改动
  COMMIT;
  ```
  运行预期：在 `READ COMMITTED` 下，别的事务未 `COMMIT` 的写入对本事务不可见（避免脏读）。
- **常见误解**：
  - 误解：级别越高越好 → 正解：越高并发越低，按业务容忍度选，并非全用串行化。
  - 误解：可重复读能避免幻读 → 正解：标准 SQL 中可重复读不保证防幻读，只有串行化能（MySQL InnoDB 例外，靠 MVCC+间隙锁）。
  - 误解：隔离级别解决所有并发问题 → 正解：还需配合锁/乐观并发控制，且要注意长事务放大锁竞争。
